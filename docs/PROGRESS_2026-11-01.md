# Avance — 1 de noviembre de 2026

## Resultado

El bloqueo de ejecución ARM quedó resuelto **en CI Linux/QEMU**. Ahora se ejecutan siete pruebas ARMv7 con dos compiladores: GNU cross y Zig 0.15.2 con target glibc 2.31. Incluyen cargar el plugin mediante dlopen, llamar su entry point, probar parámetros/transporte/escenas/concurrencia y ejecutar el guard de asignaciones en procesamiento. La interoperabilidad JSON/Python → binario → C++/ARM conserva exactamente los bytes.

Esto no equivale a una prueba del host Akai, Hakai, controladores, voltajes ni deadlines físicos. No se accedió a la MPC.

## Implementado y probado

| Cambio | Evidencia | Límite actual |
|---|---|---|
| Ejecución Linux ARM | GNU y Zig: siete tests cada uno bajo QEMU cortex-a9 | Sysroot Ubuntu; no imagen Hakai ni kernel/controlador MPC |
| Gates con timestamps | FIFO SPSC sin coalescer, subida/bajada separadas incluso a un sample | Clase de transporte/captura independiente; no conectada al callback VST ni a un dispositivo |
| Inicio y parada del pipeline | Inicio sólo después del paquete de ceros; stop descarta eventos no enviados, termina el paquete parcial y envía ceros | Acknowledgement significa bytes aceptados por backend, no voltaje medido |
| Fallos | Overflow, timestamp inválido, máscaras no reservadas, heartbeat detenido, timeout y reloj invertido | El caller debe seguir ejecutando tick; un backend que bloquee incumple el contrato y el timeout no puede interrumpirlo |
| Escenas coherentes | Sólo audio aplica parámetros de la escena; barrera mientras existan escenas pendientes, rechazo si cola llena | Cambiar escena reinicia slew; no morphing ni continuidad garantizada |
| Múltiples productores de estado | Callers de chunk serializados en control; un consumidor audio; TSan | getChunk devuelve memoria propia hasta el siguiente getChunk: el host debe copiarla antes de otra petición |
| Autoría JSON | Compilar/decodificar escenas y aplicar presets; límites/NaN/duplicados/ciclos/checksum comprobados | Herramienta offline; no navegador de escenas ni lector JSON dentro del VST |
| Ocho interruptores de salida | Parámetros añadidos 44–51; índices anteriores intactos; máscara atómica sin pérdida de cambios concurrentes | Touch y Q-Links todavía sin probar en MPC |

El plugin sigue con **salida física ausente**, genera silencio y muestra voltajes simulados. La clase EventPipeline no se presenta como un sender de producción ni como solución de coordinación con pistas CV nativas.

## Archivos clave

- `include/mpccv/event_pipeline.hpp`: handoff acotado producer/worker, reserva de máscara, heartbeat y cierre.
- `include/mpccv/backend.hpp`: paquetes con máscaras para no tocar salidas ajenas a la reserva.
- `src/vst/plugin.cpp`: barrera de escena y ocho switches atómicos.
- `tools/scene_tool.py`, `scenes/generic-performance.json`: escena editable y preset aplicado fuera de tiempo real.
- `tools/run_armv7_qemu.py`, `tools/build_armv7.sh`, `tools/fetch_zig.py`: builds y ejecución verificables.
- `.github/workflows/offline.yml`: CI macOS, Linux nativo y ARM/QEMU.
- `tests/event_pipeline_test.cpp`, `tests/scene_io_test.cpp`, `tests/test_scene_tools.py`: regresiones y roundtrip.

## Pruebas del código final

**PASS:** make -B check nativo, ASan/UBSan en suite completa, TSan para pipeline y host VST, guard C++ new/delete, simulación de ocho salidas, seis tests Python, generación/geometry check de skin con 52 parámetros y revisión visual del Overview.

**PASS ARM/QEMU:** core_test, backend_test, graph_test, event_pipeline_test, vst_host_test, rt_test y scene_io_test, tanto GNU como Zig.

Evidencia estructurada: `evidence/2026-11-01/`. Los reportes registran el commit de código, SHA-256 de fuentes y binario, versiones de compiladores/QEMU, duración de cada prueba y enlaces de CI. Las duraciones de emulación no sirven para estimar latencia o carga de la MPC. La evidencia del 19 de octubre queda como registro histórico.

El artefacto GNU usa las bibliotecas del cross-sysroot Ubuntu y no es un candidato de distribución para Hakai. Zig mantiene el target anterior arm-linux-gnueabihf.2.31; ejecutarlo contra bibliotecas Ubuntu más nuevas no prueba disponibilidad de dependencias en el firmware real. El binario local actualizado está en `build/armv7/mpc_cv.so`; no se publica ni instala.
