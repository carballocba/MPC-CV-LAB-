# MPC native UI foundation

`ui/native/params.json` and `layout.conf` define six native MPC pages. The plugin exports 44 stable-index parameters: 0 simulation arm, 1 output bitmask, 2–25 eight nodes × rate/scale/type, 26–33 read-only simulated voltages, 34 transport state, 35 fault, 36–43 virtual source selections for eight outputs. Append future parameters; do not reorder these.

OVERVIEW shows all eight simulated voltages, transport, arm and fault. ENGINES provides eight node controls with two Q-Link banks. ROUTING maps each output to Off or node 1–16; references beyond a scene's node count resolve to Off. DEVICES describes the generic profile foundation. SCENES explains host state recovery; a touch scene browser is not implemented. SETTINGS contains the output bitmask (15 first four; 255 all eight) and diagnostics. Arbitrary bitmask entry is a developer-stage control, not the intended final live-performance UX.

Q-Link assignments are generated in native `Q-Links.json`, not simulated MIDI input. The plugin exposes normalized VST parameters and human-readable rate/scale/voltage displays. Hardware Q-Link behavior, polling of read-only meters and touched controls are unverified on MPC. No desktop VST editor window is advertised; the MPC host owns the native skin. Snapshot previews render static artwork/touch zones and can show blank live-value fields; they are not hardware screenshots.

Build inputs are regenerated by `python3 tools/generate_ui.py`. For actual skin output, supply a reviewed framework checkout at `26e4581dee9ed128a5b34e306134f1fc97b7ff0e` and a Python environment with Pillow 12.0.0:

```sh
MPC_VST_FRAMEWORK=/absolute/path/to/mpc-vst-plugins tools/build_skin.sh
```

In this workspace Pillow is isolated under `build/python`; use `PYTHONPATH="$PWD/build/python"` when reproducing. Artifacts appear under `ui/native/build/skin/`; seven preview PNGs appear under `build/` (six pages, two engine banks). Generation and offline skin geometry checks completed without warnings. Nothing is copied to MPC or registered.

Scene control mappings are stored as future assignment metadata. Current Q-Link maps come from the skin and are not dynamically replaced by scene loading. Scene morphing, destination-specific device browsers, MIDI note envelopes and a physical backend remain pending.
